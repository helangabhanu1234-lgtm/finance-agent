# Bugs found in live testing (llama3.2, 24 Oct) and how they were fixed

Evidence: `logs/agent.log`, `logs/trace.jsonl`, web-UI trace. Every fix has a regression test in `tests/test_regressions.py`.

| # | Symptom (what the user saw) | Root cause (found in the code/logs) | Fix | Test |
|---|---|---|---|---|
| 1 | "Convert 50 USD ... add as Shopping" saved the expense **3-4 times** (ids 110, 112, 113, 114); Shopping showed 437 % over budget | (a) repeat guard allowed an identical call twice (`seen > 2`); (b) a number-guard reminder made the model start over, and cosmetic argument changes (`description` "None" vs "shopping", extra `currency`) bypassed the raw-argument comparison | `add_expense` identity = (amount, category, date, currency); a second save in the same request is refused (`error_type: duplicate`). Any identical tool call is refused the 2nd time. Reminders now say "do NOT call any tool again" | `DuplicateExpenseTests` |
| 2 | "**Cannot reach Ollama**" after "Make it for last month instead" although Ollama was running | `friendly_error()` mapped *every* timeout to "cannot reach". The log shows each failure came exactly 180 s after the previous step = `OLLAMA_TIMEOUT` (slow CPU, model unloaded after the default 5 min) | Timeout has its own message; real exception logged (`OLLAMA CALL FAILED`); timeout 600 s; `keep_alive=30m`; explicit `num_ctx`/`num_predict`; old tool results shortened in history; reminder messages removed after each request | `OllamaErrorTests`, `HistoryTests` |
| 3 | Wrong figures: Food "Rs. 2,500" (tool: 22,510), "Total income Rs. 1,893,061.01" (does not exist), "Rs. 16,601.00" (saved: 16,600.51) | Number guard only checked that a figure exists *somewhere* in the conversation, and accepted +/-0.51 even for figures written with decimals; after 2 reminders it only appended a warning | Figures with decimals must match to 0.01; **category-pair guard** (a line naming one category must use that category's figures); after 2 failed reminders the answer is **rebuilt from the tool results** (`agents/formatters.py`) instead of showing wrong numbers | `FigureGuardTests`, `NumberGuardLoopTests` |
| 4 | `-500` answered with "A valid example of a negative amount is -500.00" | The model was asked to explain the error and invented an example | `UserInputError` -> `error_type: invalid_user_input`; the agent answers from the tool's own message ("amount must be greater than 0. Nothing was saved. Example: ...") with **one** model call | `InvalidUserInputTests` |
| 5 | Web UI showed nothing for minutes, then `WinError 10053` traceback | Trace was sent only after the whole request; closing/reloading the tab broke `wfile.write` | `/api/chat` streams events live (NDJSON); client disconnects are ignored; clickable example prompts (the hint text was being pasted into the message box) | `WebStreamTests` |
| 6 | `logs/agent.log` contained fake `USER: hello` / errors | Unit tests logged into the real log file | Logger disabled during tests | - |

Before each demo or video: run `reset_demo.bat` (the database currently contains the duplicate rows created by bug 1).
